# What the four reference extensions actually do

Design evidence for the quick replies and guided turns discussion, 21 November 2026. The first comparison captured four ideas but grouped substantially different features under “suggestions,” “guidance” and “revision.” This review follows the input, request, visible result and saved state of each tool. A candidate here is available for discussion. Inclusion does not commit the project to building it.

The reference extensions were installed in a disposable research host for observation. The product and release checks use one active preset and Roleplay Instructions as the sole extension.

## Roadway 0.4.0 — ideas attached to a particular reply

| Step | Behavior in the pinned source | What it would mean in Roleplay Instructions |
| --- | --- | --- |
| Choose an idea generator | A named Roadway prompt preset contains suggestion wording, extraction strategy and impersonation wording. The user can edit the prompt, select a preset, or ask to choose one each time. Choosing at generation time updates the selected preset. Restore Default resets the default suggestion text, extraction strategy and impersonation template together and selects the default preset. Separately, a connection profile controls the request. | Expose the three choices separately. People may want different generators for player actions, NPC actions or writing advice, all using the same model. Preserve which generator and wording produced an older set of ideas. [Settings and picker][rsettings] |
| Ask about this point in history | The message button finds the character from the target avatar. It builds context through the clicked message, can include group names, uses the profile's formatting settings, and appends the brainstorming prompt with a configurable role. There are separate settings for context and output budgets. The default asks for six player actions. | “What could I do here?” on an older turn is distinct from “What now?” A reusable result needs a source chat, message and swipe. Add a choice about drafting against that historical context or branching there. [Request construction][rrequest] |
| Read the result | Bullet extraction recognizes numbered periods and hyphen prefixes at the start of a line. With extraction disabled, or no extracted options, the original reply can still be read. Partial matches keep only the recognized options. | Raw reading, individually actionable options and incomplete extraction are three different states. Preserve the provider response and allow manual selection from it. [Formatter and parser][rformat] |
| Save, reopen or replace candidates | A small system message contains rendered HTML plus a numeric target, raw text and option array. Running again updates the existing item for that target. New items are pushed to the chat array and visually inserted after the target. Several UI lookups assume target index plus one. The chat-change handler reattaches option handlers for the last message if it is a Roadway result. | In our extension, prefer a reply attachment keyed to a stable turn revision, with explicit regeneration and optional previous batches. Exercise older messages, message deletion and reopening. An extra system-message row can also change tools that count raw messages. [Creation and replacement][rrequest] · [Rebinding and group hooks][rhooks] |
| Use, edit or write as the player | **Use** replaces the contents of the composer and can submit immediately. Inline edit saves on blur or Enter. **Impersonate** uses the selected option as a prompt variable and reads the currently selected Roadway preset. It can call the main impersonation command or a separate profile that streams into the composer. The separate profile path builds context again without the original end index. | Preserve “use wording verbatim,” “draft in my voice” and “send” as independent capabilities. Show the scope and the overwrite behavior. A saved candidate can outlive both its original preset and its original scene. [Option actions][ractions] |
| Automate | Manual operation and automatic generation are separate. Solo rendering can start generation automatically. Group mode waits for the group wrapper to finish for supported generation types. Auto-open is a display preference. | Let the user choose when suggestions cost a call independently of where or how the result opens. Count one group turn at the selected boundary. [Event handling][rhooks] |

## Pathweaver 1.5.0 — brainstorming, directing and scheduling

| Surface | Behavior in the pinned source | Candidate or engineering implication |
| --- | --- | --- |
| Style library and toolbar | Four main categories and nine genre categories have different prompts. Users can add, edit and delete custom styles, change built-in prompts and icons, choose which styles appear, and configure the bar. Generated suggestion cards are separate from those style definitions. | A pinned **Shocking arc** recipe, an editable genre brainstorming prompt and one specific generated idea can each be favorites. Give each a distinct source and restore target. [Categories][pcategories] · [Style management][pstyles] |
| Director | Single Scene combines multiple inputs into one scene. Story Beats requests a suggestion for each beat. Directions can be added and reset, and the input and results views are separate. Director bypasses ordinary category caching. | A player could enter “introduce the courier,” “delay revealing the letter,” and “let the scout interrupt” together. Decide whether the resulting beats remain alternatives, become an editable ordered plan, or are scheduled individually. [Director request][prequest] · [Director UI][pdirector] |
| Context and World Info | Builds its own context from the most recent 2–10 raw message objects, strips markup and caps each cleaned message at 10,000 characters. Optional card description, scenario and lore have separate switches. Its lore lookup accepts up to ten enabled, nonempty entries of order 250 or higher, searching embedded then fallback sources. Order is a filter, not a record of a keyword match or confirmed delivery. | Our picker should make “use the entries actually recalled for this turn” a separate context source from “also consult this book.” A high-order secret or a hidden system note cannot be assumed to be player knowledge. [Context extraction][pcontext] |
| Model and display | Supports main API, a named connection profile, Ollama, and an OpenAI-compatible endpoint. The streamed path can progressively complete cards. For some host/profile paths a failed streaming attempt can fall through to a second non-streaming request. Parsers handle separators, paragraphs, numbered and emoji-led blocks. A title without a description can receive the placeholder “Click to use this suggestion.” | Show an unfinished candidate as unfinished. Never send a UI placeholder. Preview the actual payload. Streaming, retry policy, endpoint, context and generation cost are independently configurable decisions. A phone pointed at localhost reaches the phone itself. [Generation routes][prequest] · [Parsing and streaming][pparse] |
| Delivery and cache | **Copy**, **Insert**, **Send** operate on the description. Insert can append or replace. Send writes the composer then clicks the host send button. OOC/Director wrapping produces visible text. Ordinary category results can be reused by category and chat. Chat change and generation end clear the cache. The event registration does not include a specific edit/swipe-selection invalidator. | Offer clipboard, insert at cursor, append, replace, visible send, and hidden direction as distinguishable destinations. A cache should include the selected swipe, changed source text, caller and settings. [Cards and delivery][puse] · [Events and queue cleanup][pschedule] |
| Surprise Me | A separate request creates text before it is needed. Queue records contain a key, category, text, base message count and delay. Delay can be fixed or random. Generation-end processing compares current chat-array length against the stored base, injects the text with its own key at depth one, and clears an already injected item on the next check. Removing an item or clearing the queue also clears active injections. The runtime injected flag is omitted from storage. | A prepared surprise, a directive actually present in a request and an event that happened in fiction are three observable facts. Reopening, retrying or cancelling between those points needs distinct treatment. Offer reveal/spoiler and countdown controls. [Enqueue][penqueue] · [Save and restore][pqueue] · [Execution][pschedule] |
| Endless Surprises | Once an injected item clears, the optional endless setting can generate a replacement of the same style in the background after a delay. It checks whether generation is busy before and after waiting. | Three different costs belong on the menu: draw locally from an existing event book, spend one call to prepare one surprise, or authorize recurring calls. Provide a way to stop recurrence while retaining already prepared items. [Rearming][pschedule] |

## Guided Generations 1.7.8 — directing a turn and maintaining guidance

| Workflow | Observed implementation | Candidate or engineering implication |
| --- | --- | --- |
| New character reply | Treats composer text as direction, fills an editable prompt, installs an ephemeral chat-depth injection and triggers generation. In a group the user can choose a responding member or cancel. The original input is restored in a finally block. | **Direct the next NPC reply** can be a first-class action independent of a visible player message. The model writing the passage, the NPC taking an action and the group member generating a reply are separate fields. [Guided response][gresponse] |
| Alternate reply | Can navigate from an earlier swipe to the last existing swipe before generating a fresh alternative. Handles blank direction separately, checks injection readiness, invokes host swipe-right, restores input and cleans up the named injection. | Our guided swipe must additionally reconcile the old reply's book updates. Existing alternate swipes must remain selectable. Avoid one shared injection name across tools or concurrent requests. [Guided swipe][gswipe] |
| Continue | Extends the existing reply and has separate undo-last-addition and revert controls. The implementation emits message-edit events and saves the chat for those reversals. | A user might want to continue the same conversation beat without choosing a new swipe. Preserve a boundary for the appended segment and refresh facts on undo. A new ending does not require rewriting the opening. [Continue and undo][gcontinue] |
| Player drafts | First-, second- and third-person buttons use separate prompt templates. The first-person path selects direct profile/preset generation or a host command. The recovery helper keeps up to ten inputs/results in module memory, skips a consecutive duplicate and cycles past the current text. The quick reply bar can be integrated into the same button area. | Perspective, iterative drafting, an original fragment and recovery have value with any preset. Persist drafts per chat if recovery across reloads is promised. On a phone, expose text labels for perspective and destination. [Impersonation][gimp] · [Recovery][grecover] · [Controls][gindex] |
| Persistent guides | Situational, character thinking, clothes, state, rules, custom and custom-auto guides have different lifetimes from a one-shot direction. Guide execution can refresh or replace a named injection, set depth/role and create an optional chat note. Edit/show/flush interact with the host's script injections. The flush menu includes a broad clear-all operation. | Separate what is visible in chat from what remains active in prompts. Show the actual guide text, owner and lifetime. “Remove our guides” must target only our IDs. Link a stored fact or rule to its original book when appropriate. [Guide runner][grun] · [Management modules][gguides] |
| Tracker and automatic work | A chat-specific tracker can run a determination step and an update step using separately configured prompts/profiles. It reads the existing tracker injection and writes the new one. The main hook checks generation type, dry run and enabled guides and can run several guides sequentially. A separate optional post-generation tool can create a corrected swipe. | One tap can indirectly cause multiple model requests. Expose the existing memory owner and cost before enabling a second tracker. A numeric counter can update locally. A narrative judgment may require generated content. [Tracker][gtrack] · [Hooks][gindex] |
| Utilities and alternate APIs | Simple Send can post a user message without a model reply. Other tools include draft spellchecking, targeted correction, editing greetings and managing custom fun prompts. Greeting editing has a direct completion path and a host swipe path. Its swipe helper syncs the old extra data and appends both text and per-swipe metadata. Its client resolves presets against chat/text completion mode and separates profile-owned connection fields from prompt settings. | Keep **polish my draft**, **change this greeting**, **revise wording** and **correct a world fact** available as different shortcuts. A prompt role switch alone cannot reproduce them. Determine capability per action and preserve the profile the user is writing with. [Tools][gtools] · [Swipe metadata][gmeta] · [Client][gclient] |

## Recast 1.86 — revising text after it exists

| Workflow | Observed implementation | Candidate or engineering implication |
| --- | --- | --- |
| Define a pipeline | A Recast preset contains ordered, enableable passes. The shipped definitions include Grounding, Character Behavior Validator, Prose Rhythm and Repetition Hammer. Each pass has its own prompt, optional prefill/role, profile and context options. The UI supports adding/removing, sorting, compact controls, a larger pass editor and managing presets. | “Review for flattening” can be either a zero-extra-call Reanchor instruction on the next reply or a separately requested revision of existing prose. Offer both as candidates and show the difference in timing and cost. [Default passes][rdefaults] · [Pass editor][repass] |
| Build each request | Can include card details, a scene window, World Info, named World Info outlets and resolved macros. Context can be a text block or role-separated messages. Optional regex processing distinguishes input/output and depth. The history slice is relative to the end of the live chat even when a caller supplies text from an older message. | For historical work, limit input to the target timeline unless the user explicitly wants a retrospective edit with later knowledge. Preserve protected host markup or state separately from visible prose. [Pass builder][rebuild] · [Role/depth filter][reregex] |
| Execute and display | Each enabled pass consumes the preceding result. Generation can stream, hide output until the last pass or replace paragraphs dynamically. The progress bar has Stop. A failed request can retry with a fallback profile or without streaming. The pass catches failure and can return its input. | Distinguish unchanged prose, a skipped pass and a failed pass. A strict one-call shortcut cannot silently retry. Stream into a draft buffer if the extension's story state watches the real message. [Requests and pipeline][repipe] |
| Review and reuse | The diff has original/transformed text, an editable result when enabled, accept/reject, and step navigation when at least two passes have snapshots. The extension saves the original, transformed text, snapshots and pass names on the message and can reopen the review. Reopening and rejecting writes the stored original. | Restore the shortcut template, undo the latest edit and revert the reply to its pre-pipeline original are different actions. Show a conflict if the user edited the message after the saved comparison. [Diff and persistence][rediff] |
| Run beyond the newest reply | Includes single-message, bulk range, subset-of-passes, toggling and profile slash commands. The auto path handles several generation types, skips the opening message and user messages, and has special handling for a continuation prefix. Macros expose original/latest and pass output. Compatibility logic watches a specific other extension's mutex. | A shortcut can link to a revision pipeline or a specific pass. Bulk revisions need a call estimate and ordered memory reconciliation. One published compatibility hook does not establish that arbitrary third-party writers have finished. [Commands][recmd] · [Auto hook][reauto] · [Macros][remacro] · [Compatibility][recompat] |
| Interact with memory | Inline streaming can temporarily assign text to the live message. The refresh helper emits a host message-edited event. Our extension listens for that event to reconcile stored facts. Rejecting a preview or revisiting a saved diff can therefore matter to other listeners. | Test the event sequence and final stored facts in our own revision workflow. Debouncing alone cannot distinguish a paused review from an accepted correction. [Message updates][reupdate] · [Our listener](../src/engine.js) |

## What we exercised in SillyTavern

Two disposable data directories ran SillyTavern 1.19.0 with the four pinned extensions installed together, Chromium, and synthetic chat content. The primary checks below exercised the shipped JavaScript. Roadway's connection service and Pathweaver's OpenAI-compatible endpoint received fixed responses. Additional checks called the actual exported Guided Generations and Recast helpers inside the running host. The surprise experiment emitted host events deliberately. These checks establish specific behaviors. They do not measure model writing quality, prove every backend works, or establish compatibility with Roleplay Instructions' memory engine.

| Check | Input and action | Actual result |
| --- | --- | --- |
| Roadway extraction, editing and Use | Click Generate Roadway on a message with a fixture profile. Return three lines beginning with `1.`, `2)` and `- `. Change the first option to “Read the old map.” with Edit and Enter. Type “Original draft” in the composer and click Use. | The first and third lines became options. The second disappeared from the choices. The edited wording reached the composer and replaced “Original draft”. The option array held the edit. The stored message HTML and raw-text field did not contain the edit at that point. |
| Pathweaver append | Select the OpenAI-compatible route, disable streaming and enable append. Start with “My draft.” Select Context-Aware, supply two titled cards separated by a line containing three hyphens, and click Insert on the first card. | The draft was preserved. The next line read “The courier unfolds a map at the gate. ---”. Part of the separator entered the draft in this fixture. This gives us a concrete malformed-output regression case. |
| Pathweaver surprise lifetime | Seed one record in the disposable chat's saved queue with a one-message delay. Emit chat change to load it. Append a dummy user message. Emit generation end twice and inspect the host injection and queue after each step. | Before the first event the queue held one item and the prompt was empty. After the first event the prompt contained the prepared direction. After the second the prompt was empty and the queue had zero items, even though the probe had issued no intervening model request. A queue transition alone cannot certify delivery. |

These are helper-level checks, separate from generating an impersonation through a provider. |
| Recast pass management and review | Open the settings drawer, add a pass, open its full editor and close with Done. | Recast historical context | Add two later messages containing unique markers. Roadway's automatic submission and its choice of impersonation API were distinct controls. Recast exposed automatic run, skip diff, hide-until-last and editable diff independently. |

### Cold first-use observations at 390 px

A separate reviewer received the disposable URL, a goal (find a story direction or guide a draft), and no design history. In a character chat they found the clapperboard, opened **Director**, selected **Story Beats**, added a fourth field and typed a beat. The on-screen single-scene and story-beat descriptions explained the choice. They had to inspect title attributes to identify several other touch icons.

* **Pathweaver.** The compass offered Copy, Insert and Send. On a title-only result, Insert toasted success and placed the literal “Click to use this suggestion” in the composer. This is a different failure from the extra separator in the structured fixture.
* **Guided Generations.** The book/counter opened a menu containing Situational, Thinking, Rules, Custom and Show Guides. Choosing Custom returned to chat without an editor or visible acknowledgment on that path. The reviewer could not tell what to do next.
* **Roadway.** The message ellipsis exposed an unlabeled road icon. Tapping it without a selected profile gave an actionable explanation. The profile selector was the first control in Roadway Settings.
* **Recast.** A message action opened an original/final comparison. Two passes reported missing-profile errors, followed by “Pipeline complete!” and Accept on identical text. The reviewer chose Reject. “Finished” and “successfully revised” need different user-visible outcomes.

## Decisions the original comparison left out

These are independent product choices. A person can, for example, want a local surprise queue, a model-assisted player draft and no automatic revision calls.

| User intent | Meaningfully different choices | Tradeoff to discuss |
| --- | --- | --- |
| “Give me ideas at this point in the story.” | Generate alternatives on demand; always generate a batch; roll existing book entries locally; pin an earlier batch to a particular swipe. | Generated ideas can reflect the scene. Local choices cost no call and honor a curated pool. Automatic batches spend a call even when the user ignores them. |
| “Help me write my half.” | Insert the idea literally; expand it in first, second or third person; revise the user's existing text; generate several drafts and keep the original. | Insert is immediate. Drafting can preserve voice but must show what it used and where the output will land. Draft history scoped to a chat costs local storage. |
| “Make something happen.” | Send visible direction; queue one hidden nudge for a specific NPC reply; add it to an ordered scene plan; prepare a concealed surprise for a future beat. | Visible direction is easiest to edit in history. Hidden and delayed directions need a pending view, an owner and a receipt. Neither establishes that the event actually happened. |
| “Occasionally remind the model.” | Use Reanchor/Emotionality scheduling from the book; arm a one-shot override; maintain an editable standing guide; update a tracker periodically. | A saved reminder is zero extra calls. Regenerating a persistent guide may cost calls and may conflict with a more recent fact. Expose lifetime, owner, exact text and last update. |
| “Change that reply.” | Guided swipe; continue with an appended segment; edit a greeting as a new alternative; run one or several reviewable prose passes; repair an incorrect source fact and regenerate. | Alternatives preserve history. Inline edits suit corrections. Only accepted changes should reconcile facts and summaries, including when the user returns to an older swipe. |
| “Give me reusable controls with any preset.” | Standalone definitions, linked book entries and supported Keel actions translated from JSON into extension-owned operations. | Links follow the external owner's behavior. Copies are portable but can drift. Import must show dependencies, hidden hooks, call costs and exactly what Restore restores. |
| “Let me see just enough on my phone.” | Pinned text buttons; one searchable launcher; actions attached to messages; expandable candidate cards; optionally advancing streamed cards and pass progress. | Message actions make the target explicit. A launcher scales better for large sets. Phone controls need visible names, preserved composer focus and purposeful empty/error states. |

## Walkthrough using the supplied sets

1. **Reanchor personality.** A writer has half a player reply typed and wants the next NPC reply to respect its card. Choosing a saved Reanchor version should be able to queue it while preserving the draft. “Help me polish what I typed” is another operation with a different input, output and call cost. Choosing Reanchor must not implicitly submit the player's text.
2. **Shocking arc.** A writer locks the driver, rolls the remaining enabled ingredients and chooses immediate delivery, future delivery or “use as a starting idea.” Only the last choice needs a brainstorming call if requested. A forced direction has a receipt, while the accepted story record is derived from the resulting fiction. A guided swipe can change the outcome.
3. **Random writing and Emotionality.** A selected style can apply just once, stay active for an explicit duration, or inform a prose revision after the fact. The app must distinguish a manual instruction from the book's normal probability rule. The receipt should tell the user whether one or both sources requested the same wording.
4. **Keel.** Map supported menu actions into our library with their actual lifetimes and dependencies, and identify unmapped commands in the import report. “Advance time,” “prepare a hidden twist,” and “create a chapter dossier” require different state, call and undo contracts. A translated action can offer a built-in extension workflow while preserving the original script for comparison. [Six-file inventory](quick-replies-audit.md)

## Verification still needed if these features are built

The four reference UIs loaded together. The probes did not run the proposed feature, a paid provider, a complete group conversation, mobile TauriTavern, or an end-to-end multi-extension memory rollback. Release evidence should include captured requests and actual chat/book state before and after failure, reject, retry, group generation, chat switch, branch, old-message edit, batch delete and restore. Treat a selected source, a registered injection, a request containing it, and a fact present in accepted prose as four distinct observations.
