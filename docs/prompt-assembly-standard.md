# Prompt assembly standard

Review baseline for November 2026. Apply to ordinary replies, guided turns and additional model requests. For each affected route, record which blocks are stable, what changes them, where changing content goes, and what the host and provider actually support. Recheck the provider documentation when a model, API or host adapter changes.

| Zone | Typical contents | Placement and invalidation |
| --- | --- | --- |
| Stable prefix | Standing instructions, unchanged preset and persona material, reusable examples, output schema and tool declarations where applicable | Keep the effective prefix identical across comparable requests. Preserve role and block order and consistent serialization. A real edit, preset switch, schema change or persona change can legitimately change the prefix. |
| Growing history | Accepted chat history and durable summaries with known source coverage | Append accepted turns to preserve the shared prefix when supported. Rebuild affected history on a swipe, branch, deletion or edit. Update summaries at their configured boundaries and preserve current facts. |
| Volatile tail | Current scene changes, triggered recall, one-use cues, action checks, correction details, the latest user contribution and the current output request | Keep changing blocks as late as the host and their instruction roles allow. Keep the immediate task and its most relevant evidence close together. Preserve override semantics and character knowledge boundaries. |

Preserve the active preset's roles and intentional placement. Prefer stable high-priority instructions early and concise turn-specific instructions near the point of generation. Include task-critical facts where they can be used and omit irrelevant recall before moving or repeating material. Long-context studies document position effects in retrieval tasks. The best order for a particular story task still needs validation with the target model. Cache reuse cannot justify stale facts, weakened instruction priority or degraded generation quality. [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)

Cache support depends on the connection, API, model, minimum input length, retention and host behavior. OpenAI documents prefix-based reuse, Anthropic documents implicit and explicit caching and cache breakpoints, and Gemini distinguishes implicit and explicit caching with support varying by API and model. Where a route exposes cache controls, select boundaries from the actual stable prefix. Preserve cache scope across comparable turns within the authorized context. Inspect the final request after host templates, macro expansion and lore injection. A common prefix is an opportunity for reuse. Provider-reported usage establishes actual hits when the route exposes it. [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) · [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) · [Gemini context caching](https://ai.google.dev/gemini-api/docs/caching)

## Review and QA

- Capture consecutive requests with the same preset and connection. Compare the reusable prefix and identify the first changed block. Repeat with changed cues, triggered lore and a routine new turn. Audit macro expansion, ordering, schemas and other per-request fields that could change the prefix.
- Exercise a preset or persona edit, a swipe, a branch, a deleted turn and summary rollover. Confirm the expected reset point and assert that invalidated material stays out. Check roles, freshness and where the current instruction lands.
- Record the route, model, shared prefix, and cache read/write metrics where available. Label unavailable metrics as unavailable. Use fixtures for structure. When evaluating competing prompt orders on a supported model, check whether it follows the latest direction, grounds its answer and respects knowledge boundaries alongside token reuse and latency. Use the standing authorization rules for any live model tests.
